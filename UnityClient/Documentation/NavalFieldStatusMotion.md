# 海域场地、状态与资源变化动效

本次实现使用现有 Unity UI、代码绘制和实际战斗数据。范围为六系海域场地与战斗 HUD 的状态、资源反馈；发牌、弃牌由独立任务维护。

## 状态与资源反馈

### 真实数值与表现分离

- `CoreGameplayBattleStatusHud.RefreshBattleStateChangePresentation(root, battle)` 是规则提交后的接入点。只刷新当前保留的战斗根与同一阶段；准备转炮战、炮战转接舷时，新界面自行建立静默基线。
- 状态 `Amount` 与资源余额立即使用核心规则的当前值。动画只绘制槽位周围的短暂高亮和独立差值文本，不用旧值插值替换当前值，不重新计算伤害、支付、奖励或存档。
- 状态以 `CoreBattleStatus.Id` 匹配。新增显示“新增”；可比较的整数或百分比显示真实增减；复合值、持续时间及规则说明变化显示“更新”，避免把“伤害×次数”等复合格式当作层数。
- 消失状态立即移出有效状态集合，并停用悬停说明与射线。`Retiring Status {id}` 仅保留短暂消退图像与布局占位，结束后销毁，避免其他有效图标提前挤到消退图像上。

### 实际资源范围

紧凑 HUD 沿用三行布局，不新增虚构的“六系余额”：

| 行 | 实际显示与跟踪的数据 |
| --- | --- |
| 第一行 | 能量及上限、行动点／抵达后剩余行动点 |
| 第二行 | 常规与临时法力、雷链、潮势、对敌咒痕 |
| 第三行 | 火药、炮弹、木板、药品库存 |

`BattleResourceChangeTracker` 读取独立数值，不解析显示字符串。法力分别跟踪常规、临时两个池，因此常规 `+1` 与临时 `−1` 即使总量不变也会分别呈现。只有上限变化时显示“上限±N”，不会报告为获得资源；到达上限而实际余额未变时不播放假增益。

烈焰通过燃烧、引火等实际状态体现；血契通过实际血契状态与现有生命支付、伤害、治疗反馈体现。玩家没有另行构造失血余额，接舷敌方已有的失血规则也未被替换。

### 时序、重复刷新与抑制

- `BattleHudChangeMotion` 使用 `Time.unscaledDeltaTime`。新增、变化及资源差值为 0.72 秒，状态消退为 0.42 秒；这些局部表现不会延长出牌或移动的输入锁。
- 第一次构建、全界面重建与停用后重新建立快照均不从零播放增益。重复提交同一显示快照不会重复播放，动作提交后的反馈与最终保留刷新可以并存。
- 选船、移动动画或到达朝向选择期间，状态行沿用原有隐藏规则。真实状态仍立即刷新，表现保留“上次可见快照”；恢复可见后只展示净变化一次。期间出现又消失且从未呈现的状态不误报新增或消退。
- 退出、根节点停用／销毁会取消局部表现并清理待播放的状态变化。装饰子节点 `Battle HUD Change/Delta` 不接收射线，不修改原图标、余额文本或槽位的布局位置与缩放；有效状态的 tooltip 保持可用。

### 实现与验收入口

- `Presentation/Runtime/BattleStatusRow.cs`：有效状态快照、隐藏期间净变化与消退占位。
- `Presentation/Runtime/BattleHudChangeMotion.cs`：有限时长高亮、差值文本和纯代码边框绘制。
- `Presentation/Runtime/BattleResourceChangeTracker.cs`：独立数值池跟踪与静默基线。
- `Presentation/Runtime/CoreGameplayBattleStatusHud.cs`、`CoreGameplayCompactBattleHud.cs`：实际 HUD 接入。
- EditMode 过滤名 `BattleHudStateChangeTests`：权威数字、差值与重复刷新、状态消退、tooltip／射线、隐藏恢复、临时法力、容量变化、停用与静止布局。
- PlayMode 集成验收使用真实动作与截图检查，最终结果与报告见本文末尾。

## 六系海域场地表现

### 六系常驻纹样

`NavalFieldGraphic` 沿用现有海格颜色、世界坐标和范围边框，仅使内部纹样轻微运动，不摇动整块场地或文字。

| 系别 | 常驻表现 |
| --- | --- |
| 火场 | 三道火舌轻摆，细小火星向上消退 |
| 奥术折射阵 | 内外菱形慢速反向旋转，外圈符文刻度随行 |
| 诅咒禁域 | 交叉封锁线保持稳定，三道短纹向内收束 |
| 潮汐水流 | 三道波纹沿规则指定的水流方向移动，方向箭头固定 |
| 雷栅 | 三道折电低幅偏移与局部间歇亮起 |
| 血誓阵 | 血滴轮廓缓慢搏动，内部短纹响应同一节拍 |

每格 `我/敌` 归属、类别简称和真实剩余回合数继续由 `NavalFieldBoardOverlay` 刷新；布局、边框、有效范围和水流箭头不参与缩放或摇动。摆放与路线预览仍使用独立 Graphic，不继承常驻纹样动效，也不改变卡牌目标验证。

### 铺设、替换、消散和实际触发

- 铺设使用 0.40 秒展开的局部纹圈。覆盖使用旧类型颜色的收束碎纹，与新类型展开同时呈现；移除及到期使用 0.46 秒向外消散的短纹。活动格立即反映最新规则，旧格只保留短暂装饰，不继续表示有效范围。
- 真正触发使用 0.58 秒局部明亮纹圈及放射短线。反馈来自 `RecordNavalFieldTrigger` 成功写入规则 ledger 后的只读事件，不根据数值变化或“船在场地里”推测，铺在船脚下不会假装已经触发。
- `CoreNavalFieldState` 保存最多 128 条运行时表现事件，携带坐标、种类、实例、归属、方向、受影响船和单调序号。覆盖与到期在实际移除前记录，因此同次结算中的触发后移除、玩家回合开始清空规则 ledger，都不会丢失真实反馈。
- 事件标注实际移动触发来源。主动或被动入格、水流移动触发先进入有上限的待播队列；只有对应移动 revision 已开始显示，且船中心距事件格不超过 55 米时才播放，移动结束可处理跳过的中间帧。回合开始/结束的脚下触发与诅咒结算直接反馈，不等待不存在的移动。资源、伤害及状态数值仍在规则提交时立即更新。

### 生命周期与性能

`NavalFieldMotion` 只消费一次权威事件，使用非缩放帧时间推进表现。Overlay 是唯一带当前战术 revision 的事件同步入口，避免不同 `LateUpdate` 顺序提前消费。检查点或规则预览的 `Copy()` 不复制表现历史，恢复后建立静默基线。

控制器停用或销毁、场地隐藏、组件停用、应用暂停及失焦都会取消短暂反馈并跳过已结算序号；恢复后不会补播旧奖励或重新支付。常驻表现保留当前相位，规则本身完全不受影响。绘制复用 Graphic 与有上限的结构体列表，不每帧创建 GameObject、材质或纹理；没有活动格与反馈时不反复标记空网格重建。

专项 EditMode 过滤名为 `NavalFieldMotionTests`，覆盖事件顺序与上限、真实触发去重、ledger 清理后的事件、预览复制隔离、移动 revision 与显示位置门槛、暂停/owner 销毁，以及六系内部动画和固定投影边界/方向。集成 PlayMode 以方法前缀 `NavalFieldStatusMotion_` 筛选，使用真实选牌确认、移动及回合按钮，并验证场地根节点停用期间发生的变化在重新启用后静默建立基线。
