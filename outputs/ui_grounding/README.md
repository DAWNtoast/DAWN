# 港口场景融合与落地修正

本轮目标：让陈列物真正依托地板、支架、桌面和船台，不靠悬浮矩形、整体缩放或新增大面积背景遮罩掩盖问题。

## 改动范围

- 港口后勤：六个港口分别校准左右干平台上的落脚点；采购牌恢复完整图片、宽高比及两只支脚；每个脚有小范围接触阴影。船体与装备共享柔边水线裁剪，遮住水下船底，保留各港原画浅水，检查项和采购按钮继续保留。
- 部件商店：按 25 套原型的真实轮廓与承托点计算陈列，不再用通用方形图片尺寸估算。支架采用前后遮挡，商店与羊皮纸详情使用相同几何；帆去掉重复桅杆，炮台/仪器不再套错架子。库存与购买规则未改。
- 卡组工坊：四个箱子落在中央地毯，标签置于箱体前板，脚下有接触阴影。
- 远航派遣：保留桌子原始比例，三张海图贴合桌面透视；清除常驻的彩色大光圈。
- 藏宝图桌：缩小海图并映射到桌面梯形平面；选中航线的详细信息放在独立阅读区。
- 仓库：十种物资的数量标签对应到原画中的木桶、货箱与帆布，不再贴一层独立物资图标。
- 船坞：使用新合绘背景让三艘船与船台产生承托及前栏遮挡；左后船位继续显示可更换部件的轻帆船。保留四个购船/切换入口。
- 卡组构筑和出航配置：修正骷髅装饰压住标题、禁用卡牌文字过暗、教程按钮/船名/属性互相压叠。
- 酒馆、船员档案、港口入口、派遣部署已检查，未对没有明显问题的布局做强行重排。

悬停策略：部件、卡箱和桌上海图只改变亮度/光晕，不整体放大，因此不会再次把落脚点从地面抬起。

## 编辑与验证

原有 `Assets/_Project/Scenes/UIPreviews` 中的独立预览场景继续使用同一套运行时布局代码，等待 Unity 重新编译后重新打开场景即可看到。无需重建玩家存档。

验证使用隔离项目 `D:/Game/tmp/regional-ports-check-20260906`，没有关闭用户编辑器、保存用户当前场景或变更真实游戏存档。该项目的公司名/产品名与主项目不同。

截图工具：`Shattered Sail → Art Review → Capture Port Scene Grounding`。每次生成新目录；现有目录非空时拒绝覆盖。五类商店陈列页为临时固定美术样例，明确标注为非真实库存。

首轮回归中，旧测试要求“悬停必须放大部件、箱子和海图”，与此次保持落地的新需求冲突。测试已改为验证高亮仍触发、缩放和位置保持不变；购买、货币、装备、卡组、派遣、补给和航行断言保留。

美术来源、最终路径、完整提示词和弃用的透明尝试见 `shipyard_art_notes.md`。

- 已完成 29 张 1920×1080 布局截图：灰鸥港 14 个功能/详情页、其余五港的部件商店与后勤页、五类部件的固定陈列样例。样例库存仅用于美术验收，不写入实际库存。

- 包含最后的船体水线遮挡修正后，EditMode 回归 **74/74**、PlayMode 回归 **18/18** 全部通过。
- 最终测试记录：`UnityClient/Artifacts/port-grounding-editmode-waterline.xml` 和 `UnityClient/Artifacts/port-grounding-playmode-final.xml`。六港用例校验水线裁剪的下沿、桅杆及船角留白、所有模块层的原始尺寸/UV/位置/顺序，并确认没有额外绘制水面矩形。
- 中间版本保留在 `UnityClient/Artifacts/PortGroundingV1`、`PortGroundingV2`、`PortGroundingV3`，便于对照，不覆盖旧验收图。
