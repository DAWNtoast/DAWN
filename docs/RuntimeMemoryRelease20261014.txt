改动
返回主菜单时释放导航标题、罗盘和面板框的静态 Sprite 引用，并解除生成 Sprite 的 DontUnloadUnusedAsset 标记，纳入已有的 UnloadUnusedAssets 流程。活跃界面的 Image 仍持有资源，不直接销毁正在使用的 Sprite；重新进入航海时按需加载。没有降低纹理分辨率或画质，也没有在每帧增加 GC 或资源卸载。
卡牌说明将“自身贡献上限”缩写为“本牌上限”，保留数值与机制，避免长说明过度缩小字体。
更新旧迭代遗留的测试前提和断言，使其匹配当前十张最低卡组、市场详情入口、正方形海图、固定画面比例和现役卡牌规则。游戏战斗及经济数值未为迁就测试而修改。

内存测量方法
Unity 6000.3.23f1，Windows x64 Mono，非 Development Player；RTX 5080，Direct3D 12。
基线源码：a239d860b539a201b4c67191f2e746501198029d。
诊断构建版本元数据：基线为 0.3.20261014-memory-audit，优化为 0.3.20261014；公司/产品隔离身份和探针 DLL 相同。基线二进制保持锁定，没有为改版本名重建。
顺序为基线1、优化1、基线2、优化2、基线3、优化3，每轮全新进程，同一份诊断探针 DLL。
每轮 57 个检查点覆盖港口设施循环、六港人物详情和配件店、航行天气、四次海战/冲撞漫画/接舷及三次游戏场景与菜单往返。外部每 250 毫秒采样 Private Bytes 和 Working Set，以 UTC 对齐稳态采样窗。
使用隐藏窗口和 1920×1080 受控渲染，保留实际生产 Canvas 内容，每个稳态点确认渲染帧数。因此数值包含诊断相机与 RenderTexture 开销，不能直接当作普通可见窗口的绝对占用；没有测量独立显存。Private Bytes 与 Working Set 是不同指标，不能相加。
诊断使用独立公司/产品存档身份。统一探针的 DLL 后处理仅用于诊断包；正式包必须重新构建并确认不含探针或测试程序集。

测量结果
六轮全部完成且退出码为 0，共 342 个检查点，每轮实际渲染约 13,480 帧。
三轮各三次场景往返共九次菜单检查中，基线每次残留 navigation_header_v3、navigation_compass_v3、navigation_panel_frame_v3 三张纹理，优化版每次为零；菜单总纹理数从 73 降至 70，Sprite 从 9 降至 6。两版本各自的设施循环和菜单往返中，受检 GameObject、Graphic、纹理、Sprite、材质、音频和字体数量没有持续增长。

诊断期间无意外游戏 Error/Exception；六个探针进程均在最后采样之后的退出阶段出现 ComputeBuffer 回收与 D3D12 4096 B 未释放资源警告，已保留原始日志，不能表述为日志零警告。正式包的独立检查结果另行记录。
