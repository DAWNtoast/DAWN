改动范围
新增八个真实层级 Prefab：主菜单首页、主菜单设置、成就、新游戏确认、存档提示、游戏内设置、保存并返回主菜单确认、航行/事件顶栏。此前已有的两个港口顶栏 Prefab 继续使用，并调整其图片依赖的持有方式。脚本通过序列化组件引用绑定当前存档、设置、时间、状态、成就和按钮事件，不再逐节点创建这些固定界面。
主页 Prefab 包含 Canvas、固定画面范围、黑边、背景、标题及五个菜单按钮。其依赖不包含可选弹窗的美术；弹窗在首次使用时实例化。成就模板保留八行，根据当前页绑定内容，不预载全部成就图片。
航海顶栏只用于航行和事件阶段，复用标题、状态、时间轴、船舱与设置控件；战斗继续使用原有区域页眉。市场、仓库保留已有局部更新；地图格子、战斗、设施商品等动态正文仍按原逻辑生成。本轮不代表整个游戏或所有界面已改成 Prefab，也没有调整战斗、交易、存档格式或经济规则。

复用与资源释放
菜单存档提示、游戏内设置、返回主菜单确认及航海顶栏各最多保留一个按需创建的实例。主菜单设置关闭后仍保留原有草稿；游戏内设置重新打开会重读已保存设置，关闭放弃草稿。设置和返回确认事件使用版本校验，旧回调不能操作新一次打开的草稿；航海顶栏在重绘时重新绑定两个按钮，再应用当前教学步骤的限制。
保留的港口顶栏和背景在停用时清除图片引用，只保留当前港口需要的主题；离开航海时清除保留顶栏的框架和指南针图片。设置弹窗关闭后清除大纸张引用，并合并安排一次延迟资源回收。Prefab 模板不直接持有这些按场景绑定的大图，避免模板成为额外的常驻引用。
资源清理解除缓存引用及生成 Sprite 的 DontUnloadUnusedAsset 标记，让原有 UnloadUnusedAssets 流程根据活跃对象决定回收。不会直接销毁仍由活跃 Image 持有的借用纹理或 Sprite，不增加每帧强制 GC。少量固定对象的保留与大图片的释放分别处理，不能据对象复用直接推断总内存下降。

家具遮罩与素材保持
六港家具的背景覆盖遮罩改为使用原算法离线生成，运行时直接加载原尺寸、无损 R8、线性空间的遮罩。原 Atlas 与 coverage 均关闭 CPU 像素副本；不再在打开配件商店时读取整张 Atlas 并分配数组生成遮罩。
六张原始家具 PNG 与准确基线逐字节相同，SHA256 核验通过；其导入设置的语义变化仅为关闭 Read/Write。新增六张 coverage PNG 均为 1536×1024。六港逐源像素比较测试全部通过，验证新遮罩红通道与旧运行时算法输出一致，包含原抗锯齿边界。相关证据为 furniture-source-preservation.json 与 EditMode-integrated01.xml 中的 BakedCoverageMatchesOriginalAlgorithmAtEverySourcePixel 六项用例。
本轮未生成新美术、未调用外部图像 API，也未恢复或更新已退役的 UIPreviewsForMe 内容。固定结构、文字、几何、字体、皮肤和输入行为按原实现迁移；视觉对照结果与覆盖范围见下文。

性能对照口径
测量工具使用独立诊断公司/产品身份及隔离工程，不读写正式游戏的 PlayerPrefs、角色存档或 journal。准确基线为本记录顶部的提交，优化版本为本轮待发布源码；生产源码清单、探针源文件及二进制 SHA256 分开记录。
已按基线1、优化1、基线2、优化2、基线3、优化3交替运行六个全新进程，共同使用同一份 canonical v2 探针 DLL 和相同分析版本。每轮 68 个检查点，覆盖原有设施循环、六港人物与配件店、航行天气、海战/漫画/接舷及场景往返，并增加固定菜单/设置/确认弹窗的首次与重复打开检查点。
加载时间分别统计生产操作回调耗时 CallbackMs、诊断绑定与强制布局 BindAndLayoutMs、目标界面首个实际渲染帧 FirstRenderedMs，以及生产淡入和延迟回收完成后的 ReadyRenderedMs。场景加载还记录目标 sceneLoaded 时间；LoadScene 回调仅代表请求提交，不能当成场景加载完成。v2 用目标场景 handle 和真实相机回调确认目标画面，避免将旧场景最后一帧计为新场景首帧。
首次指新进程首次访问，没有清空操作系统文件缓存，不等同冷盘加载。缺失、被后续操作替代或未完整配对的数据不作为零值；暖操作先在单轮取中位数，再比较三轮中位数和范围。固定等待、内存稳态窗口不冒充加载耗时。
使用 Unity 6000.3.23f1、Windows x64 Mono 非 Development Player、隐藏窗口与共同 1920×1080 SDR RenderTexture，VSync 关闭、目标 60 FPS。生产 Canvas 临时绑定受控相机，采样点核验实际渲染帧数。相机回调反映 CPU 侧渲染提交，不是 GPU fence、显示器实际呈现或普通可见窗口交互延迟。
外部每 250 毫秒采样 Private Bytes 与 Working Set，以 UTC 对齐每个稳态点 1.5 秒的窗口；漫画瞬态另行标记。两种内存指标不相加，没有独立显存测量，数值包含共同诊断相机/RT/探针开销，不能当作普通窗口绝对 RAM。活动 GameObject/Graphic 计数不包含停用缓存，不能据此宣称全部对象无增长；需结合缓存生命周期测试、已加载资源和外部内存趋势判断。
截图使用额外独立进程，不混入六轮性能对照。截图读回和 PNG 编码产生额外分配，最后截图之后的全进程峰值也不代替游戏步骤峰值。完整流程、诊断 PASS 或理论分配减少均不自动证明性能改善，结论以原始实测数据为准。

重复循环与资源证据
优化版设施第 1→10 次循环 Private 三轮分别增加 15.078、14.453、3.805 MiB；第 10→20 次三轮均持平。托管 reserved 三轮约 11.33→15.13→15.13 MiB；Unity reserved 全程约 208.793 MiB。第 10→20 次托管 used 与 Unity allocated 波动均小于约 0.10 MiB，资源计数稳定，未见此区间持续增长；前段增长不能完全归因，也不能据 20 次循环证明长期无泄漏。活动对象计数排除停用 Prefab，需结合生命周期测试判断。
36 份六港商店库存确认原 Atlas 和 R8 遮罩均由可读转为不可读，原尺寸和格式保留。首航基线仍持有多个已离开港口的 header，优化版三轮均为零，是减少不可见大图持有的直接证据。末次菜单三个航海目标纹理在两版都已释放，此项来自此前优化，不能重复算作本轮新增收益。
六轮无新增运行异常匹配；两版每轮均有相同的 D3D12 info-queue 初始化提示、退出 ComputeBuffer 由 GC dispose 提示及退出 4096 B unreleased resource 提示。这些既有提示尚未解决，正式成品冒烟也记录到相同提示。无新增异常不等同绝无 bug。
